## Scan warning disposition and scope

Both scanner warnings point to literal `YOUR_RUNTIME_PASSWORD` / `YOUR_MIGRATION_PASSWORD` examples with `HOST`, not working credentials. These are PostgreSQL connection-string templates consumed only by the server and migration script, not browser navigation or HTTP requests. `src/server/db/connection.ts` and `scripts/connection.mjs` pass the configured value directly to the PostgreSQL driver with verified TLS; neither logs it. Real values stay in ignored `.env.local`. Disposition: **false positives for exposed cleartext credentials; no source change needed**. This is a reviewed result with warnings, not a zero-warning scan.

The CA-file path is trusted server configuration, never request input; TLS still verifies the certificate. The ledger migration only removes client privileges and does not modify existing applied migration checksums. Hosted tests create randomly keyed temporary sessions and delete only those sessions in teardown. New E2E tests use synthetic credentials from ignored configuration, with tracing disabled. Paid Plus was not run. Completion is limited to M0 development acceptance, not production deployment approval.
