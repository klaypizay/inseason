# Drill locks and quick edits

Move the existing drill lock onto each practice card: “Lock this drill” and “A regenerated practice plan will not affect this drill.” Draft/Use controls persist lock changes. Quick edit offers Edit manually and Ask AI tabs. AI requests change only the selected unlocked drill, keeping its identity, minutes, position and the rest of the practice unchanged. Results remain drafts for coach review. If there are unsaved manual edits or locks, the AI action saves that draft and queues the revision in the same transaction; any validation/quota/stale failure rolls back both operations.

Rafter secure design: extend the strict, bounded practice-intent schema with an optional UUID blockId and require a nonempty brief for targeted edits (600 characters maximum). The existing session-authenticated action and owner-scoped repository resolve the target from the saved practice, never trusting an arbitrary caller-supplied drill. Reject absent, foreign, locked, past or completed targets and stale versions. Optional draft content is validated by the existing save path; it is accepted only for a targeted drill request. Existing RLS, advisory locks, revision checks and idempotency keys apply to the atomic save-and-begin transaction. This adds no new endpoint, dependency, schema migration, credential or permission.

The coach's prompt stays inside untrusted JSON context, not the instruction string. The provider has no tools and retains the existing token/output limits, timeout, repair limit and per-program quotas. At output validation, merge only the requested drill into the original practice; ignore proposed changes to other drills, the practice name, weekly objectives and allocations. Reject changed duration, ID or lock state and continue existing resource checks. Rendering is escaped React text. Saved version/generation records use existing tenancy, TLS, retention and audit metadata; do not log prompts or credentials.

Threat model: a forged block ID cannot select another coach's content or an unrelated practice; lock state is enforced on the server before generation and on output, not by the prompt. A malicious prompt cannot expand the replacement scope or execute tools. Stale/concurrent saves cannot overwrite newer versions; quota failures cannot leave a half-saved draft. A model that returns invalid output leaves the previous plan available. Generated drills need coach review; existing guidance avoids invented observations and participation assumptions. Test these boundaries with synthetic fixtures and mocked provider responses. No paid AI verification or remote Rafter scan is needed for this iteration; scans and pushes remain deferred per user direction.
