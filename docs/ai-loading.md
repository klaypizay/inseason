# Branded AI progress overlay

Show the same modal progress treatment for roadmap, assessment, weekly-priority, practice and drill generation, both during the initial action and while a queued/running attempt is active. Use the existing concentric-circle brand motif: a stationary filled center and a rotating outer ring, dark green on cream with the existing light-green accent. Reduced-motion preferences disable rotation. Explain the result in plain language without invented progress percentages or completion times.

The native modal dialog sits above Quick edit, makes the underlying page inert, receives focus and exposes an announced status. It restores scrolling when unmounted. Request errors, polling errors and terminal run states remove the overlay, making errors and saved content accessible. Normal manual saves do not trigger the AI loader. Existing server generation, ownership, validation, quotas, prompts, transport and persistence are unchanged; this change adds only presentation and client pending-state handling. Rafter surface check: no new SQL, user input fields, data processing, credentials, endpoints, model invocation paths or dependencies. Remote scans and pushes remain deferred by user preference.

Clear prior errors synchronously when a coach retries, before starting the React transition, so an old error cannot suppress the loader while the new request is pending. Browser coverage includes a rejected drill edit followed by a successful retry, preserved manual edits, modal focus, restored page scrolling, reduced motion, and complete assessment, roadmap, practice, drill and weekly-priority generation with the free fixture provider.

Review: presentation-only props and SVG; no HTML injection, added requests, dependencies or changes to generation permissions. Typecheck, lint, scoped formatting and the production build passed. Desktop and mobile loader screenshots were visually inspected. Verification uses temporary synthetic coaches and no paid model calls.

Results: the full mobile planning flow passed, including failure/retry and reduced-motion checks; desktop weekly-priority generation passed. Initial desktop practice coverage caught and led to the synchronous error-reset fix.
