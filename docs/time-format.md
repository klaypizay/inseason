# Coach time format

Default to 12-hour times with AM/PM. Save an optional 24-hour preference in Profile (Coach), and use it in schedules, practice plans, print views, conflict messages and time entry. Stored local times remain HH:mm; this is a display preference, not a timezone or schedule change.

Rafter secure design: the browser submits the existing preferences action through the authenticated session. A strict Zod enum admits only `12-hour` or `24-hour`; account identity comes from the session, never form input. The parameterized repository upsert retains its account advisory lock and revision check. Migration 014 adds a constrained, non-null column with a 12-hour default to the existing forced-RLS preferences table, inheriting its permissions and account-deletion lifecycle. Existing preferences, times, content and revisions remain intact. The value is a low-sensitivity account preference, covered by the existing database storage/TLS and backup policies; no new secrets, logging, dependencies, endpoints or AI calls are needed.

Threat model: an attacker submitting a foreign account ID or arbitrary format is rejected by the strict schema; RLS and session-derived ownership prevent cross-account reads/writes. Concurrent stale saves remain rejected. Render with escaped React text, and use bounded time choices that emit canonical HH:mm or blank for optional events. The server's existing schedule validation remains authoritative. The main correctness risks are noon/midnight conversion, unintended time changes while toggling formats, and blank all-day events; verify those along with saved preference isolation and persistence. No new privilege, disclosure, resource-exhaustion or credential boundary is introduced. Remote scans and Git pushes remain deferred per the user's request.
